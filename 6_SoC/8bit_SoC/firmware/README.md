# CPU ROM 프로그램 — 계산기 펌웨어 `calc.asm`

[계산기 통신 규약](../02_design/calculator.md)을 구현한 ROM 프로그램이다. v2 1단계(2026-11-24)는 CALL/RET 루틴과 POW·GCD·SQR·`ERR OVER`를 포함한다. 어셈블된 코드는 1067워드로 ROM 4K 워드의 약 26.1%다. CPU v2는 VR-015를 통과했으며, 이 펌웨어·통합의 VR-016과 v2 보드 실물 시험은 아직이다.

## 구조

| 부분 | 내용 |
|---|---|
| main (레지스터 묶음 0) | RAM 변수 초기화, IRQ_EN = RX_VALID, EI, 대기 루프 |
| RX 인터럽트 처리 루틴 (벡터 워드 2, 레지스터 묶음 1) | 진입마다 SP=0x8040을 설정한다. 문자 1개를 꺼내 줄 상태를 갱신하고, 줄 끝에서 검사·계산·응답 뒤 줄 상태를 지운다. 처리 중 문자는 RX FIFO(16바이트)에서 기다린다 |
| ADD·SUB | 부호 확장 뒤 16bit 덧셈·뺄셈 |
| MUL·POW | `mul16`: 16bit 크기 × 8bit 크기를 시프트·덧셈으로 계산한다. CPU 시프트 명령 대신 ADD/ADC로 두 배를 만든다. POW는 이를 반복하며 signed16 넘침을 검사한다 |
| DIV·GCD | `divmod`: 반복 뺄셈으로 몫·나머지를 구한다. DIV 몫은 0 방향, 나머지는 A의 부호다. `gcd`는 절댓값에 유클리드 호제법을 적용한다 |
| SQR | `sqrt`: A에서 1·3·5…를 빼며 정수 제곱근을 센다. 음수 A는 `ERR RANGE`, B는 사용하지 않는다 |
| 응답 | `print`로 숫자를 출력하고 `txwait`로 TX_EMPTY를 기다린다. CRLF 포함 최대 17바이트 DIV 응답은 " R:" 앞에서 다시 기다린다 |

`mul16`·`divmod`·`print`·`txwait`는 다른 루틴을 부르지 않는다. `power`·`gcd`는 LRH/LRL을 PUSH/POP하며, `power`는 반복 횟수도 저장한다. 처리 루틴의 관측 최대 스택은 3바이트(0x803F~0x803D), 변수는 0x8000~0x801A의 27바이트다. SP=0x8040과 루틴 배치는 구현 기본값이며 사용자 직접 선택으로 기록하지 않는다. [v2 설계안](../02_design/v2_design.md) 초기 스택 배치 제안보다 낮게 두어 변수·스택을 캐시 64바이트 주소 창 안에 둔다.

## ISA 제약에 맞춘 방식

- X는 LDXH·LDXL·INX로만 바뀐다. 변수는 고정 주소를 쓰고 응답 문자열은 X를 TX_DATA에 둔 채 `LDI` + `ST`로 한 글자씩 쓴다. ROM 문자열 표와 `.byte`는 쓰지 않는다.
- 공용 루틴은 12bit 절대 word 주소의 CALL과 LR 기반 RET로 부른다. 출력 복귀용 `V_PHASE`는 제거했다.
- JMP·조건 분기는 여전히 ±128워드 상대 주소다. 먼 곳은 `t_*`·`s_*` 중간 점프를 거친다. 2단계 긴 JMP는 미구현이다.
- TX 인터럽트는 쓰지 않고 `txwait` 하나를 공유한다.

## 전후 수치 (v2 1단계)

비교 기준은 전 `3bdd3cfa4cd0ba1905441b6df395c0aac9b23b31`의 v1 펌웨어와 후 `761dc9d512c3f61313a6f2021b3a19896d01a5c3`의 v2 펌웨어다. 같은 `cpu8_asm.py`로 두 소스를 어셈블해 집계했다. 새 연산 추가를 함께 포함하므로 크기 차이를 루틴화만의 효과로 해석하지 않는다.

| 항목 | 전(v1) | 후(v2 1단계) |
|---|---|---|
| 어셈블된 word 수 | 853 | 1067 (+214) |
| ROM 4096 word 대비 | 약 20.8% | 약 26.1% |
| `V_PHASE` 정의 / 주소 피연산자 사용 | 1 / 2 | 0 / 0 |
| TX_EMPTY 대기 루프 본문 수 | 3 (`er_w`, `px_w`, `rm_w`) | 1 (`tw_l`, `txwait` 안) |
| 첫 본문을 제외한 복사본 수 | 2 | 0 |

word 수는 어셈블러 `assemble()` 결과의 주소 항목 수다. `.org`로 비운 word 1까지 포함한 주소 범위는 각각 854·1068워드이며 ROM 하드웨어 용량은 모두 4096워드다. 루프는 주석을 제외한 `LDI Rn, ST_TXE` 뒤의 AND·조건 분기 본문을 세었다.

### 연산별 관측 최악 응답 클록

후 수치는 2026-11-24 Claude 자체 XSim 실행 로그를 확인해 옮겼다. `761dc9d`의 `tb/soc/tb_soc8_top.sv`와 `firmware/calc.asm`, `scripts/run_soc8_top_tb.sh`를 사용한 결과다. Codex가 이번 문서 작업에서 시뮬레이션을 다시 실행한 결과는 아니다. 전 펌웨어에는 이 측정이 없어 재측정하지 않았다.

| 연산 / 이름 | 전(v1) | 후 fast DRAM | 후 fast BRAM | 후 real 115200 (두 모델 동일) |
|---|---|---|---|---|
| ADD | 측정 없음 | 341 | 341 | 1492 |
| SUB | 측정 없음 | 277 | 277 | 1561 |
| MUL | 측정 없음 | 725 | 757 | 1890 |
| DIV | 측정 없음 | 1365 | 1365 | 2189 |
| POW | 해당 연산 없음 | 2389 | 2389 | 3617 |
| GCD | 해당 연산 없음 | 565 | 1173 | 1360 |
| SQR | 해당 연산 없음 | 469 | 469 | 1669 |
| GCE (잘못된 이름) | 측정 없음 | 213 | 213 | 1552 |
| POX (잘못된 이름) | 측정 없음 | 181 | 181 | 1401 |
| SQX (잘못된 이름) | 측정 없음 | 181 | 181 | 838 |

단위는 100 MHz 클록(10 ns)이며, **입력 줄의 첫 줄끝 바이트 정지 비트 시작부터 응답 첫 시작 비트까지**다. 수신 확정·해석·계산·송신 시작을 포함하고 응답 전체 송신 시간은 포함하지 않는다. 정지 비트 중간에 수신을 확정하므로 정지 비트 끝을 기준으로 삼지 않으며, TB는 음수 측정값을 실패로 판정한다.

fast는 3.125 Mbaud로 UART 대기를 줄인 계산 경로 비교용이며 순수 산술 실행 시간은 아니다. real은 115200 bps에서의 같은 구간 응답 지연이다. fast에는 무작위 120줄이 추가되어 시험 입력 집합도 다르다. 값은 시험 집합에서 관측한 최댓값이며 전 입력의 상한이나 v1 대비 속도 향상을 입증하지 않는다. real이 더 큰 원인은 분석하지 않았다. `stack_bytes=3`은 같은 시험에서 관측한 처리 루틴 최대 스택 사용량이다. 상세 시험·제약은 [통합 TB](../tb/soc/README.md)를 따른다.

## 빌드

```sh
python3 1_RTL/2_TINY_PROJECT/CPU/8bit_CPU/TOOLS/cpu8_asm.py 6_SoC/8bit_SoC/firmware/calc.asm -o /tmp/calc.mem   # 저장소 루트 기준
```

어셈블러는 `.equ`·문자 상수·CALL·RET·PUSH·POP을 지원한다. 생성한 `.mem`은 저장소에 넣지 않는다. 시뮬레이션은 [통합 TB](../tb/soc/README.md) 실행 스크립트가 어셈블하며, 보드 빌드는 `soc8_top.ROM_FILE`로 넘긴다.

## 시험

[통합 TB](../tb/soc/README.md)는 일곱 연산·오류 5종·경계값·연속 줄·parity 오류·빠른 baud의 무작위 120줄을 기준 모델과 대조한다. 기존 로그에서 두 DRAM 모델의 fast·real 실행 성공, 펌웨어 변이 18/18 검출, TB·PC 기준 모델 824,586줄 차이 0을 확인했다. 이는 시뮬레이션·모델 대조이며 v2 보드·MSPM0 시험이나 VR-016 판정이 아니다.
