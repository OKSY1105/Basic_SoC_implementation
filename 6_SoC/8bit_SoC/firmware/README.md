# CPU ROM 프로그램 — 계산기 펌웨어 `calc.asm`

[계산기 통신 규약](../02_design/calculator.md)을 구현한 ROM 프로그램이다(③ 통합 3단계, 2026-11-04). 853워드로 ROM 4K 워드의 21%를 쓴다.

## 구조

| 부분 | 내용 |
|---|---|
| main (레지스터 묶음 0) | RAM 변수 초기화, IRQ_EN = RX_VALID, EI, 대기 루프 |
| RX 인터럽트 처리 루틴 (벡터 워드 2, 레지스터 묶음 1) | 진입 1회에 문자 1개. STATUS의 수신 오류 flag를 보고 지운 뒤(W1C) RX_DATA를 pop하고, 줄 상태(RAM 변수)에 따라 한 글자씩 해석한다. 줄 끝(CR·LF)에서 검사·계산·응답 송신 뒤 줄 상태를 지운다. 처리 중에 온 문자는 RX FIFO(16바이트)에서 기다린다 |
| 계산 | ADD·SUB: 부호 확장 뒤 16bit 덧셈·뺄셈. MUL: \|A\|를 \|B\|번 더한다(최대 128회). DIV: 반복 뺄셈(최대 128회), 몫은 0 방향, 나머지는 A의 부호 |
| 응답 | 응답 전에 TX_EMPTY를 기다린 뒤(FIFO 16칸) 글자를 차례로 쓴다. CRLF 포함 최대 17바이트인 DIV 응답(예: `-120,11` → `DIV Q:-10 R:-10`)은 " R:" 앞에서 한 번 더 기다린다. 숫자는 10진(0이 아닌 음수에만 '-', 앞자리 0 없음) |

## ISA 제약에 맞춘 방식

- X는 유일한 주소 레지스터이고 즉시값(LDXH·LDXL)과 INX로만 바뀐다. 값을 저장하거나 계산해 넣을 수 없으므로 변수는 고정 주소(RAM 0x8000~0x8018)에 둔다. 응답 문자열도 ROM 표를 읽어 보내는 반복문이 불가능해(문자를 읽는 X와 TX_DATA를 쓰는 X가 충돌), X를 TX_DATA에 둔 채 `LDI` + `ST`로 한 글자씩 쓴다. 그래서 ROM 문자열 배치(`.byte` 추가 여부)는 필요 없다.
- CALL/RET가 없다: 공용 코드는 JMP로 들어가고, 숫자 출력 뒤 이어질 곳은 변수 `V_PHASE`(줄 끝 또는 DIV 나머지)로 정한다.
- 분기는 ±128워드 상대 주소뿐이다: 먼 곳은 무조건 분기 바로 뒤(실행 순서에 없는 곳)에 둔 `t_*`·`s_*` 중간 점프로 간다. 숫자 출력 끝에서는 줄 끝 처리(`crlf`·`line_reset`)가 멀어 같은 코드의 사본(`crlf2`)을 둔다.
- TX는 인터럽트(TX_EMPTY) 대신 TX_EMPTY 확인 방식이다. 응답은 한 번에 몰아 보내므로 송신 인터럽트가 필요 없다.

## 빌드

```sh
python3 1_RTL/2_TINY_PROJECT/CPU/8bit_CPU/TOOLS/cpu8_asm.py 6_SoC/8bit_SoC/firmware/calc.asm -o calc.mem   # 저장소 루트 기준
```

어셈블러는 `.equ`(이름 상수)와 문자 상수(`'A'`)를 쓴다(2026-11-04 추가). 생성한 `.mem`은 저장소에 넣지 않는다. 시뮬레이션은 [통합 TB](../tb/soc/README.md) 실행 스크립트가 어셈블하고, 보드에서는 `soc8_top`의 `ROM_FILE`로 넘긴다.

## 시험

[통합 TB](../tb/soc/README.md)의 `calc` 시험: TB 안의 독립 기준 모델(규약 그대로)이 줄마다 기대 응답을 만들고, 지정 사례(규약 5절 + 경계값·오류 종류), 연속 줄, parity 오류 줄, 무작위 120줄을 보낸다. 결과와 펌웨어 변이 시험은 통합 TB 문서에 있다.
