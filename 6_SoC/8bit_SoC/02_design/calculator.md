# 계산기 통신 규약 (PC → FPGA → STM32)

ROM에 미리 넣은 CPU 프로그램(계산기 펌웨어)이 UART로 받은 요청을 해석·계산하고 결과를 UART로 보낸다. 이 문서는 그 요청·응답 형식과 오류 처리를 정한다.

- 결정 기준: 사용자 확정(2026-10-24·25, 이전 기록 `(CPU)_06`) — 두 수를 먼저 보내고 연산 요청을 보낸다, ADD/SUB/MUL/DIV, 입력 −128~127, 결과 부호 있는 16bit, DIV는 정수 몫·나머지, MUL/DIV는 프로그램 반복.
- 이 문서의 규약: 2026-11-04 사용자가 Claude 추천안을 채택했다("Use the defaults"). 표에서 "기본값"으로 표시한 세부는 추천안에 없던 항목을 Claude가 정한 것이다.

## 1. 연결과 UART 설정

```text
PC TX ─────────────────────────────► FPGA UART RXD
FPGA UART TXD ─┬───────────────────► STM32 USART RX → WAT-LCD_BUTTON LCD
               └───────────────────► PC RX (결과·오류 확인, 자동 채점)
```

| 항목 | 값 |
|---|---|
| UART 인스턴스 | 1개(M9, 0xFF00~0xFF04). TX 한 선을 STM32와 PC 두 수신기에 함께 연결한다 |
| 속도·프레임 | 115200 bps, 8E1(데이터 8bit, 짝수 parity, stop 1bit). PC 터미널과 STM32를 이 설정에 맞춘다 |
| STM32 설정 | HAL 기준 `WordLength = UART_WORDLENGTH_9B`, `Parity = UART_PARITY_EVEN`(8B로 두면 데이터가 7bit가 된다) |
| 전기 조건 | 3.3 V 레벨, 공통 GND. Zybo Z7-20의 보드 USB-UART는 PS(MIO 48·49)에 연결되어 있으므로 PC는 PL 핀에 외부 USB-UART 변환기로 잇는다. 핀은 FPGA 단계에서 정한다 |

## 2. 요청 (PC → FPGA)

요청은 줄 단위다. 줄 끝은 CR, LF, CRLF를 모두 받으며 빈 줄은 무시한다.

| 줄 | 형식 | 예 | 동작 |
|---|---|---|---|
| 숫자 줄 | `<A>,<B>` | `10,20`, `-128,7` | A·B를 저장한다. 다음 숫자 줄이 올 때까지 유지하므로 같은 A·B에 연산만 여러 번 보낼 수 있다 |
| 연산 줄 | `ADD` · `SUB` · `MUL` · `DIV` | `add`, `Mul` | 저장된 A·B로 계산해 결과 줄을 보낸다. 대소문자를 구분하지 않는다 |

- 숫자: 선택적 `-` 하나 + 십진수 1~3자리. 범위는 −128~127이다. `+` 부호는 쓰지 않는다.
- 숫자 줄은 성공하면 응답하지 않는다(기본값). LCD에는 결과만 나타난다.
- 공백은 허용하지 않는다(기본값). 공백이 있으면 `ERR SYNTAX`다.
- 한 줄은 줄 끝 문자를 빼고 최대 15자다(기본값). 넘으면 줄 끝까지 버리고 `ERR SYNTAX`다.

## 3. 응답 (FPGA → STM32·PC)

모든 응답은 ASCII 한 줄이며 CRLF로 끝난다. 숫자는 십진수이고, 음수에만 `-`를 붙이며 앞자리 0은 쓰지 않는다.

| 연산 | 응답 | 예 (A=10, B=20) |
|---|---|---|
| ADD | `ADD:<A+B>` | `ADD:30` |
| SUB | `SUB:<A−B>` | `SUB:-10` |
| MUL | `MUL:<A×B>` | `MUL:200` |
| DIV | `DIV Q:<몫> R:<나머지>` | `DIV Q:0 R:10` |

- 결과 범위: 곱의 최대 16384(−128×−128), 최소 −16256(−128×127), −128÷−1의 몫 128을 포함해 모두 부호 있는 16bit 안에 들어간다. 넘침은 생기지 않는다.
- 나눗셈 부호(기본값): 몫은 0 방향으로 버리고, 나머지는 피제수(A)의 부호를 따른다. C 언어의 `/`·`%`와 같다. 예: `-7,2` → `DIV Q:-3 R:-1`, `7,-2` → `DIV Q:-3 R:1`.

## 4. 오류 응답

| 응답 | 조건 | A·B |
|---|---|---|
| `ERR DIV0` | B = 0에서 DIV | 유지 |
| `ERR RANGE` | 숫자가 −128~127 밖(예: `200,1`, `-129,0`) | 유지(덮어쓰지 않음) |
| `ERR SYNTAX` | 형식 오류: 쉼표 없음, 숫자 아님, 4자리 이상, 알 수 없는 연산, 공백, 15자 초과. UART 수신 오류(parity·frame·overrun)가 난 줄도 여기에 포함한다(기본값) | 유지 |
| `ERR NOARG` | 올바른 숫자 줄을 받기 전의 연산 줄 | 없음 |

- 잘못된 숫자 줄은 기존 A·B를 덮어쓰지 않는다.
- UART 수신 오류가 나면 펌웨어는 오류 flag를 지우고(0xFF03 W1C) 그 줄을 줄 끝까지 버린 뒤 `ERR SYNTAX`를 보낸다(기본값).

## 5. 시험 사례 (통합 TB·보드 시험 공통)

| 입력 | 기대 응답 |
|---|---|
| `10,20` → `ADD` | `ADD:30` |
| 같은 A·B로 `SUB`·`MUL`·`DIV` | `SUB:-10`, `MUL:200`, `DIV Q:0 R:10` |
| `20,10` → `DIV` | `DIV Q:2 R:0` |
| `-128,-128` → `MUL` | `MUL:16384` |
| `-128,-1` → `DIV` | `DIV Q:128 R:0` |
| `-7,2` → `DIV` | `DIV Q:-3 R:-1` |
| `10,0` → `DIV` | `ERR DIV0` |
| 숫자 줄 없이 `ADD` | `ERR NOARG` |
| `200,1` → `ADD` | `ERR RANGE` 뒤 `ADD`는 이전 A·B로 계산 |
| `10 ,20`, `1020`, `ADDX`, 16자 이상 | `ERR SYNTAX` |
| parity 오류가 난 줄 | `ERR SYNTAX`, 다음 줄은 정상 처리 |

## 6. 완료 범위 (단계)

1. 시뮬레이션: 통합 TB에서 위 시험 사례가 모두 맞는다(③ 통합·④ 통합 검증).
2. 보드 + PC 터미널: Zybo Z7-20에서 PC 터미널로 같은 사례를 확인한다.
3. STM32 LCD: STM32가 응답 줄을 LCD에 표시한다.

## 7. 펌웨어 구현 제약 (참고)

- ISA에는 CALL/RET가 없고 분기는 ±128 워드 상대 주소뿐이다. 루틴은 펼쳐 쓰고, 먼 거리 점프는 중간 점프를 거친다.
- ROM은 4K 워드다. 데이터 포트는 ROM 바이트를 하위 바이트부터 읽으므로 문자열은 `.word`에 하위 바이트를 먼저 묶어 적거나, 어셈블러에 `.byte` 지시어를 추가한다(③에서 결정).
- TX 인터럽트: TX_EMPTY 요청은 TX FIFO가 빌 때마다 다시 오므로, 한 번 진입에 TX FIFO가 찰 때까지 채우거나 보낼 것이 없으면 IRQ_EN bit 1을 끈다.
