# CPU AHB-Lite master 포트 변경안

> **상태 — 2026-11-03:** 사용자 결정 "AHB 방식으로 변경"(2026-11-02). 이 문서를 기준으로 RTL·TB를 `feat/cpu-ahb-port` 브랜치에 구현했고, Windows XSim 회귀·SVA를 통과했다(결과: `1_RTL/2_TINY_PROJECT/CPU/8bit_CPU/TEST_STATUS_PIPELINED.md`). 이 구현은 통합 브랜치 `feat/8bit-soc`에 합쳤고, 모든 모듈 설계를 마친 뒤 모듈별 Codex 검증을 거쳐 main에 병합한다(2026-11-03 작업 순서). 구현 중 바뀐 규칙은 4절 `HADDR`, 6.3절 4번, 6.4절 3번에 반영했다. 수정 위치는 [소유 경계](source_layout.md) 규칙("공용 코어를 수정하면 그 원본 한 곳에만 적용")에 따라 공용 원본 `1_RTL/2_TINY_PROJECT/CPU/8bit_CPU`이며, 현행 포트 버전은 git 이력으로 남는다.

현행 `cpu8_top`은 명령·데이터 포트 모두 `req && ready`가 참인 상승 에지에서 요청 수락과 완료가 함께 일어난다. 이 방식에 변환기를 붙이면 AHB의 주소 단계와 데이터 단계가 직렬로 이어져, 동기식 ROM에서 명령당 2클록, 무대기 slave에서도 LD/ST마다 1클록 정지가 생긴다. 이를 피하기 위해 CPU의 두 포트를 AHB-Lite master로 직접 만들고, AHB 단계를 파이프라인 단계에 맞춘다. 변환기는 없어지지만 CPU가 지켜야 할 AHB 주소·데이터·대기 시간표는 이 문서가 정한다(기존 D7 "master 어댑터 시간표"를 대체).

## 1. 변경 범위

| 구분 | 내용 |
|---|---|
| 유지 | ISA 17개와 인코딩, 3단계 IF / ID·EX / MEM·WB, 의존성 stall(forwarding 없음), 결과·FLAGS·X를 MEM/WB에서 1회 반영, 분기를 ID/EX에서 결정, fault code 1·2·3, HALT 의미, 오래된 명령의 오류 우선, 동기식 active-low reset, 디버그 출력(`o_pc`·`o_retire_*` 등) |
| 변경 | 명령·데이터 포트의 handshake: `req && ready` 1단계 완료 → AHB-Lite 주소 단계 / 데이터 단계 |
| 추가 | 인출 예비 칸 1개(IF/ID 옆), 데이터 단계 중인 인출의 기록(PC·무효 표시), 데이터 포트 ERROR 첫 클록 기록 |
| 삭제 | 버스 구조안 ①(CPU req/ready → AHB-Lite 변환기) |

## 2. 3단계 유지와 AHB 단계의 대응

| 명령 하나의 시점 | 명령 포트 | 데이터 포트 |
|---|---|---|
| IF 직전 클록 (앞 명령의 IF와 같은 클록) | 주소 단계: `HADDR` = 2×PC | — |
| IF | 데이터 단계: 명령 수신 | — |
| ID/EX | — | LD/ST 주소 단계: `HADDR` = X |
| MEM/WB | — | 데이터 단계: `HWDATA` 출력 / `HRDATA` 수신 / `HREADY` 대기 |

- AHB는 다음 전송의 주소 단계가 현재 전송의 데이터 단계와 같은 클록에 겹치도록 정의되어 있다. 따라서 명령 포트의 주소 단계는 별도 파이프라인 단계가 아니다.
- 주소를 붙잡아 두는 레지스터는 동기식 ROM(BRAM) 내부의 주소 레지스터다. CPU의 파이프라인 경계는 지금과 같은 2곳(IF→ID/EX, ID/EX→MEM/WB)이다.
- 데이터 포트는 ID/EX가 주소 단계, MEM/WB가 데이터 단계를 맡으므로, 대기 없는 slave에서 LD/ST가 MEM/WB에 1클록만 머문다(현행 무대기 TB와 같다).

## 3. 경로 구성 (1차)

```text
CPU8
 ├─ 명령 포트: AHB-Lite master, HRDATA 16bit, HPROT[0]=0
 │     └──(점대점)──▶ ROM 포트 A        0x0000~0x1FFF
 └─ 데이터 포트: AHB-Lite master, HRDATA/HWDATA 8bit, HPROT[0]=1
       └─▶ 디코더·응답 선택
             ├─▶ ROM 포트 B (읽기 전용) 0x0000~0x1FFF
             ├─▶ RAM 래퍼 ─▶ DRAM 제어기 0x8000~0x87FF
             ├─▶ AHB→APB 브리지 ─▶ UART  0xF000~0xFFFF
             └─▶ 기본 slave (ERROR)      그 외
```

1. 명령 포트도 처음부터 AHB-Lite 규약을 따른다. 2차에서 명령 포트를 버스에 연결할 때 CPU를 다시 고치지 않는다. 16bit 명령을 8bit 버스에서 2회로 나누는 변환은 2차 연결부가 맡는다.
2. 1차의 ROM 포트 A는 대기 없는 AHB-Lite slave다. 범위 밖 주소(`HADDR[16:13]≠0000`)에는 2클록 ERROR를 낸다.
3. ROM은 BRAM 2포트로 만든다. 각 포트의 주소 입력은 주소 단계의 `HADDR`이고, `HSEL && HTRANS[1] && HREADY`일 때 읽기를 실행한다. 읽은 값이 다음 클록(데이터 단계)에 나오므로 대기가 없다.
4. 데이터 포트는 1차의 유일한 master다. 중재기는 2차에 추가한다.

## 4. 포트 신호

| 신호 | 명령 포트 (`o_i_*`/`i_i_*`) | 데이터 포트 (`o_d_*`/`i_d_*`) |
|---|---|---|
| `HADDR` | [16:0] `{PC, 1'b0}` — byte 주소 = 2×PC (D2 규칙). PC 16bit 전체를 표현하므로 주소가 겹치지 않는다 | [15:0] X |
| `HTRANS[1:0]` | IDLE(00) / NONSEQ(10) | IDLE(00) / NONSEQ(10) |
| `HWRITE` | 0 고정 | ST=1, LD=0 |
| `HSIZE[2:0]` | 001 (16bit) 고정 | 000 (8bit) 고정 |
| `HBURST[2:0]` | 000 (SINGLE) 고정 | 000 (SINGLE) 고정 |
| `HPROT[3:0]` | 0010 (명령 인출) 고정 | 0011 (데이터 접근) 고정 |
| `HMASTLOCK` | 0 고정 | 0 고정 |
| `HWDATA` | 없음 | [7:0], 데이터 단계에 출력 |
| `HRDATA` | [15:0] 입력 | [7:0] 입력 |
| `HREADY`, `HRESP` | 입력 | 입력 |

- 디버그 출력은 유지한다. `o_stage_valid[0]`의 의미는 "IF 요청"에서 "IF 데이터 단계에 무효 표시가 없는 인출이 있음"으로 바꾼다.
- `HSIZE`·`HBURST`·`HPROT`·`HMASTLOCK`은 상수지만 표준 master 인터페이스를 맞추기 위해 포트로 낸다.

## 5. 데이터 포트 시간표

### 5.1 대기 없는 LD/ST

| 클록 | t | t+1 |
|---|---|---|
| 명령 위치 | ID/EX | MEM/WB |
| 버스 | 주소 단계: `HTRANS`=NONSEQ, `HADDR`=X, `HWRITE` | 데이터 단계: `HREADY`=1, LD는 `HRDATA` 수신 / ST는 `HWDATA` 출력 |
| 끝 에지 | slave가 주소 수락, CPU가 명령을 MEM/WB로 발행 | LD는 Rd 반영, 명령 완료 |

ST의 `HWDATA`는 발행할 때 저장한 Rd 값이며, 데이터 단계 동안 바뀌지 않는다.

### 5.2 연속 접근 (back-to-back)

| 클록 | t | t+1 | t+2 |
|---|---|---|---|
| 주소 단계 | 접근 1 | 접근 2 | — |
| 데이터 단계 | — | 접근 1 | 접근 2 |

의존성이 없는 LD/ST는 1클록에 1개씩 진행한다. 뒤 명령이 앞 LD의 결과 레지스터를 읽으면 기존 stall 규칙(앞 명령 반영 다음 클록에 재개)을 따른다.

### 5.3 대기 (`HREADY`=0)

| 클록 | t | t+1 | t+2 | t+3 |
|---|---|---|---|---|
| 데이터 단계 | — | 접근 1, `HREADY`=0 | 접근 1, `HREADY`=0 | 접근 1, `HREADY`=1 |
| 주소 단계 | 접근 1 | 접근 2 유지 | 접근 2 유지 | 접근 2 수락 |

1. MEM/WB는 `HREADY`=1이 될 때까지 머문다. ST의 `HWDATA`도 유지한다.
2. ID/EX의 다음 메모리 명령은 NONSEQ 주소 단계(`HADDR`·`HWRITE`·제어)를 `HREADY`=1까지 바꾸지 않는다. 대기 중 IDLE에서 NONSEQ로 바꾸는 것은 허용하고, NONSEQ를 낸 뒤에는 유지한다.
3. 대기 중 `HADDR`=X가 바뀌지 않는 것은 기존 X 의존성 stall로 보장된다. X를 바꾸는 명령(LDXL·LDXH·INX)은 메모리 접근이 없고, 대기 중인 LD/ST는 X를 쓰지 않는다.
4. 불변식: 데이터 포트 주소 단계가 수락되는 에지 = CPU가 그 메모리 명령을 ID/EX에서 MEM/WB로 발행하는 에지.
5. 뒤 명령의 주소 단계가 앞 명령과 다른 slave를 가리켜도 된다. 디코더는 데이터 단계 선택 신호를 `HREADY`=1일 때만 갱신한다(버스 구조안 ②).

### 5.4 오류 (`HRESP`=ERROR, 2클록)

| 클록 | e1 | e2 |
|---|---|---|
| 응답 | `HREADY`=0, `HRESP`=ERROR | `HREADY`=1, `HRESP`=ERROR |
| 다음 주소 단계 | 유지해도 수락되지 않음 | CPU가 e1을 기록해 두고 `HTRANS`=IDLE로 바꿔 취소 |
| CPU | 대기 | 끝 에지에서 오류 완료: fault code 3, `o_pc`=실패 명령, 정지. Rd·X·FLAGS 변경 없음 |

- AHB의 ERROR가 2클록인 것은, slave가 오류를 알릴 때 이미 다음 주소가 버스에 나와 있으므로 master가 그 주소를 취소할 시간을 주기 위해서다. 이 CPU는 e1에서 레지스터에 기록하고 e2에서 IDLE을 내므로 조합 경로 없이 취소한다.
- 오류로 끝난 전송의 쓰기·FIFO pop/push는 slave가 실행하지 않는다(D5·D9에서 slave 규칙으로 정한다).

### 5.5 정지·fault·reset·잘못된 경로

1. MEM/WB에 HALT 또는 fault 명령(불법 명령·명령 접근 오류)이 있으면 ID/EX의 메모리 명령은 주소 단계를 내지 않는다.
2. halted 이후 `HTRANS`=IDLE을 유지한다.
3. reset 중 `HTRANS`=IDLE. 진행 중이던 데이터 단계는 버스 전체 reset으로 사라지고, 이미 반영된 쓰기는 되돌리지 않는다(기존 규약 유지). RAM 래퍼의 drain 처리는 D8에서 정한다.
4. 분기는 ID/EX에서 결정되고 잘못된 경로의 명령은 ID/EX에 들어가기 전에 버려진다. 따라서 데이터 포트는 잘못된 경로의 접근을 만들지 않으며, UART pop 같은 부작용은 실제로 실행되는 명령에서만 생긴다.

## 6. 명령 포트 시간표

### 6.1 순차 인출 (대기 없음)

| 클록 | t0 | t1 | t2 | t3 |
|---|---|---|---|---|
| 주소 단계 | PC0 | PC1 | PC2 | PC3 |
| 데이터 단계 (IF) | — | I0 | I1 | I2 |
| ID/EX | — | — | I0 | I1 |
| MEM/WB | — | — | — | I0 |

명령당 1클록이다. reset 해제 후 첫 명령이 ID/EX에 들어가는 시점만 현행보다 1클록 늦다. 현행 기본 TB의 "reset 해제 후 7클록" 기대값은 바뀐다.

### 6.2 인출 예비 칸과 주소 단계 발행 조건

AHB master는 데이터 단계를 거절할 수 없다. 그래서 데이터 단계가 끝나는 순간 명령을 받을 칸이 반드시 있을 때만 주소 단계를 낸다.

1. 칸은 IF/ID 1칸 + 예비 1칸, 모두 2칸이다.
2. 발행 조건: (현재 두 칸의 명령 수) − (이번 클록에 ID/EX에서 발행되는 수) + (무효 표시가 없는 진행 중 인출 수) + 1 ≤ 2
3. 데이터 단계가 끝난 명령은 IF/ID가 비어 있거나 이번 클록에 비면 IF/ID로, 아니면 예비 칸으로 간다. 예비 칸의 명령은 IF/ID가 비는 클록에 먼저 옮긴다.
4. ID/EX가 stall하면 진행 중이던 인출은 예비 칸에 들어가고 그다음 주소 단계는 나가지 않는다. stall이 풀리는 클록에 예비 칸 명령이 IF/ID로 옮겨지므로 stall 뒤에 추가 빈칸이 생기지 않는다.
5. NONSEQ를 낸 뒤 `HREADY`=0으로 수락되지 않아도 조건은 계속 성립한다. 칸이 줄어드는 일이 없으므로 주소 단계를 유지할 수 있다.

### 6.3 분기 (taken branch)

| 클록 | t | t+1 | t+2 |
|---|---|---|---|
| ID/EX | B (분기 발행) | 빈칸 | T |
| 데이터 단계 (IF) | B+1 → 버림 | T | T+1 |
| 주소 단계 | T (분기 목적지) | T+1 | T+2 |

1. 분기는 ID/EX에서 발행하는 클록에 결정한다(현행과 같음).
2. 그 클록의 주소 단계를 분기 목적지로 바꾼다. 대기가 없으면 손해는 1클록으로 현행과 같다.
3. 데이터 단계에 있는 인출과 예비 칸의 명령은 모두 무효로 표시하고, 응답이 와도 버린다. AHB는 진행 중인 데이터 단계를 중간에 끊을 수 없으므로, 인출 취소는 응답을 받아서 버리는 것으로 정의한다.
4. 명령 포트가 대기 중(`HREADY`=0)인 클록에 분기가 발행되는 경우는 생기지 않는다. 6.2절 칸 계산 때문에, 대기할 수 있는 주소 단계(데이터 단계가 진행 중인 클록에 낸 것)는 IF/ID와 예비 칸이 모두 빈 경우에만 나간다. 그동안 ID/EX에 명령이 없으므로 분기가 발행될 수 없다. 따라서 대기 중인 주소를 분기 목적지로 바꾸는 처리는 두지 않고, SVA `a_no_redirect_held`로 이 성질을 검사한다. 분기 클록에 진행 중이던 데이터 단계가 대기하면 목적지 주소 단계가 대기로 유지되며, 이는 일반 대기와 같다.
5. 버린 인출의 ERROR 응답은 무시한다. 잘못된 경로의 명령 접근 오류는 fault가 아니다.
6. 무효로 표시된 인출과 예비 칸 명령은 6.2의 칸 계산에 넣지 않는다.

### 6.4 명령 접근 오류

1. ROM 포트 A의 ERROR 응답은 그 명령에 "명령 접근 오류" 표시를 붙여 IF/ID에 넣는다. 실제로 실행되는 경로이면 MEM/WB에서 fault code 2로 정지한다(현행 규약 유지).
2. 명령 인출은 부작용이 없으므로 ERROR 첫 클록에 다음 주소 단계를 취소할 의무는 없다.
3. 명령 포트 `HADDR`는 17bit `{PC,1'b0}`라 PC 0x8000 이상도 다른 주소와 겹치지 않는다. 기존 CPU 규약("주소·분기는 16bit에서 순환하고, 매핑 여부는 메모리의 오류 응답으로 판정한다")을 그대로 따르며, 범위 밖 판정은 ROM 포트 A(1차) 또는 2차 연결부가 한다. 초안의 "PC[15]=1이면 CPU가 직접 오류 처리" 규칙은 이 규약과 기존 시험 `fetch_wrap`(PC 0xFFFF의 HALT 실행)에 맞지 않아 쓰지 않는다.

### 6.5 정지·fault·reset

1. ID/EX에서 HALT 또는 fault 명령을 발행하거나, MEM/WB가 오류로 완료하면 이후 주소 단계를 내지 않는다(현행 인출 정지 규칙 유지). 진행 중인 데이터 단계의 응답은 받아서 버린다.
2. reset 중 주소 단계 IDLE. PC=0, 두 칸·인출 기록·무효 표시·보관한 분기 목적지를 지운다.

## 7. 상황별 단계 동작

| 상황 | IF (명령 포트) | ID/EX | MEM/WB |
|---|---|---|---|
| 데이터 포트 대기 | 칸이 남으면 인출 계속, 2칸이 차면 정지 | 발행 보류. 메모리 명령이면 주소 단계 유지 | 데이터 단계 유지 |
| 명령 포트 대기 | 주소·데이터 단계 유지 | 가진 명령은 진행, 비면 빈칸 | 영향 없음 |
| RAW stall | 2칸이 찰 때까지 인출 후 정지 | 발행 보류. 메모리 명령이면 주소 단계 IDLE | 앞 명령 계속 완료 |
| taken branch | 진행 중 인출·예비 칸 무효, 목적지 주소 단계 | 분기 발행 | — |
| 데이터 ERROR | e2부터 새 주소 단계 IDLE, 진행 중 응답은 버림 | e2에서 다음 주소 단계 IDLE, 발행 안 함 | e2 끝에서 fault 3, 정지 |
| HALT·fault 발행 | 이후 주소 단계 IDLE, 진행 중 응답은 버림 | 뒤 명령 없음 | 완료 시 halted |
| reset | 전부 IDLE, PC=0 | 비움 | 비움 |

우선순위는 현행과 같다: MEM/WB의 오류 > ID/EX의 분기·HALT > IF.

## 8. 조합 경로 규칙

1. 데이터 포트의 `HTRANS`·`HADDR`·`HWRITE`는 레지스터 값(ID/EX 명령, X, MEM/WB 상태, e1 기록)으로만 정한다. 데이터 포트 `HREADY`에 조합적으로 의존하지 않는다.
2. 명령 포트의 주소 단계는 같은 클록의 ID/EX 발행(분기 목적지, 칸 계산)에 의존한다. 따라서 데이터 포트 `HREADY` → MEM/WB 완료 → ID/EX 발행 → 명령 포트 `HADDR`·`HTRANS` 경로가 생긴다. 이 경로는 FPGA 합성 후 타이밍 확인 대상이다.
3. 모든 slave의 `HREADYOUT`·`HRESP`는 데이터 단계 상태(레지스터)와 하위 응답(`PREADY`, DRAM 제어기 `o_ready`)으로만 정한다. 현재 주소 단계의 `HSEL`·`HTRANS`·`HADDR`에는 조합적으로 의존하지 않는다. 이 규칙이 있으면 master 쪽 경로가 있어도 조합 루프가 생기지 않는다.

## 9. 검증 항목

**CPU 단독 TB (현행 TB를 새 포트로 교체)**
1. 메모리 모델을 AHB-Lite slave 2개(명령 16bit, 데이터 8bit)로 바꾼다. 고정·무작위 대기, 2클록 ERROR, 범위 밖 오류를 주입한다.
2. 기존 회귀 62개 프로그램을 새 포트에서 다시 PASS시킨다(`TOOLS/run_cpu8_tests.py`의 ISA 모델 비교).
3. `tb_cpu8_reset`의 "메모리 대기 중 reset"을 "데이터 단계 대기 중 reset"으로 바꿔 유지한다.

**SVA 검사기 (XSim)**
1. 두 포트 모두 NONSEQ 주소 단계는 `HREADY`=1까지 주소·제어를 유지한다.
2. `HTRANS`는 IDLE/NONSEQ만, `HSIZE`·`HBURST`·`HPROT`는 고정값이다.
3. 데이터 포트 주소 단계 수락 ⇔ 메모리 명령의 ID/EX → MEM/WB 발행.
4. ST의 `HWDATA`는 데이터 단계 동안 바뀌지 않는다.
5. 데이터 ERROR e2에서 데이터 포트 `HTRANS`=IDLE.
6. 무효로 표시된 인출은 IF/ID에 들어가지 않고, 잘못된 경로의 데이터 포트 접근은 0회다.
7. halted 이후 두 포트 모두 IDLE.
8. 명령 완료(`o_retire_valid`)는 명령당 1회다.

**성능 확인 (`o_retire_valid`·`o_stall`·클록 수)**
- 대기 없는 모델에서 순차 1명령/클록, taken branch 손해 1클록, stall 해제 뒤 추가 빈칸 0, 연속 LD/ST 1개/클록.

## 12. 인터럽트와 두 포트 — 2026-11-03 추가 (M11)

인터럽트 진입은 ID/EX 명령을 버리는 리다이렉트다. 분기와 같은 방식으로 명령 포트를 다룬다. 데이터 포트에는 다음 규칙을 더한다.

1. 명령 포트: 진입은 taken branch와 같다. 인출 대상이 벡터 PC 0x0002이고, 진입 뒤의 인출은 응답을 받아 버린다. 진입에는 ID/EX 명령이 필요하다. 명령 주소 단계가 붙잡힌 동안에는 ID/EX가 비어 있으므로 진입하지 않는다(SVA `a_no_redirect_held`가 진입도 포함해 검사).
2. 데이터 포트: ID/EX의 LD/ST는 발행 전부터 주소 단계를 낸다. 이 LD/ST가 버려질 때 주소 단계가 수락되면, 실행하지 않은 명령의 버스 접근이 생긴다. 그래서 두 가지를 지킨다.
   1. 인터럽트 대기 중(IE=1, 처리 루틴 밖, `i_irq`=1)에는 새 데이터 주소 단계를 내지 않는다.
   2. 이미 낸 주소 단계가 `HREADY`=0으로 붙잡혀 있으면 인터럽트를 미룬다. 그 LD/ST가 발행된 뒤에 진입한다. 붙잡힌 주소 단계를 거두지 않으므로 AHB 규칙(대기 중 주소 단계 유지)도 지킨다.
3. 결과: "데이터 주소 단계 수락 = LD/ST 발행"(SVA `a_d_issue`)이 인터럽트가 있어도 그대로 성립한다. 버려진 LD/ST는 RAM 쓰기·UART pop을 만들지 않는다(회귀 `irq_mmio`에서 pop 횟수·값이 모델과 일치).
4. `w_d_request`는 `i_irq`(레지스터 출력)와 `r_d_held`에 의존하지만 `HREADY`에는 의존하지 않는다. 대기 중 주소 단계가 바뀌지 않는다는 규칙과 충돌하지 않는다.
