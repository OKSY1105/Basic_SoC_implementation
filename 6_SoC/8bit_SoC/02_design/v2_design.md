# v2 설계안 — CPU 서브루틴(CALL·RET, 링크 레지스터)·스택(PUSH·POP)과 새 연산(POW·GCD·SQR)

- 상태: **설계안(2026-11-11)**. 1·4절은 사용자 확인("1번과 2번은 그대로", "3은 그대로 가고 4번에 거듭제곱도 포함하자"). 2·3절은 CALL·RET를 RISC 방식으로 바꾼 판이다(아래 결정). VR-014(보드 시험분)는 2026-11-19 main에 병합되었고, 구현은 `feat/8bit-soc`에서 한다. 7절(2단계)은 2026-11-20에 넓혔다.
- 결정(사용자, 2026-11-11): 새 연산 **POW·GCD·SQR**, 스택은 SAP-3처럼 SP 레지스터 + RAM 스택 + PUSH·POP. CALL·RET는 처음에 SAP-3 방식(CALL이 돌아올 주소를 스택에 2바이트 저장)으로 정했다가, 포트폴리오 비교 뒤 **RISC 방식(돌아올 주소를 링크 레지스터 LR에 저장, ARM Cortex-M·RISC-V와 같은 방식)**으로 바꿨다("일단 8bit v2먼저 하고 그 다음으로 RISC-V도 진행하는걸 생각해놔"). 순서는 1단계 이 문서 → 2단계 숫자 16bit 확장(시프트·회전과 ALU·분기 명령 포함, 7절 — 사용자 결정 2026-11-18·2026-11-20) → 그 뒤 별도 프로젝트로 RISC-V.
- 근거: 『Digital Computer Electronics』 12-10절(SAP-3 스택: SP, PUSH·POP, CALL·RET), 12-8절(레지스터 쌍). 2단계는 20장(시프트·회전), 12-6절(즉시값 명령), SAP-2·3의 논리 명령(ORA·XRA·CMA)과 조건 분기(JNZ·JNC·JM 등). RISC 방식은 ARM Cortex-M의 `BL`·LR·`PUSH {LR}`, RISC-V의 `jal`·`ra`와 같다. CPU 구조는 [README_PIPELINED](../../../1_RTL/2_TINY_PROJECT/CPU/8bit_CPU/README_PIPELINED.md), 명령 표는 [isa_table.md](isa_table.md), 계산기 규약은 [calculator.md](calculator.md).
- 아래 "기본값"은 사용자가 정하지 않은 세부를 Claude가 정한 것이다. 바꿀 수 있다.

## 1. 왜 CPU를 바꾸나

새 연산은 곱셈·나눗셈을 여러 번 다시 쓴다(POW는 곱셈 반복, GCD는 나머지 반복). 지금 CPU에는 CALL/RET가 없어서 루틴을 다시 쓰려면 복사하거나, 지금 숫자 출력처럼 RAM 변수(`V_PHASE`)로 돌아갈 곳을 흉내 내야 한다(`calc.asm` 831·966행). CALL/RET가 있으면 곱셈·나눗셈·숫자 출력·송신 대기를 루틴 하나씩으로 두고 부를 수 있다. 2단계(16bit)에서는 16bit 숫자 두 개를 레지스터 4개로 다뤄야 하므로 PUSH·POP으로 레지스터를 잠시 저장할 곳이 필요하다.

## 2. CPU v2 — 추가 명령

기존 20개 명령의 opcode·동작·클록은 바꾸지 않는다. 지금 펌웨어와 회귀 시험은 그대로 유효하다. 빈 opcode 중 0x0E~0x13·0x16(7칸)과 0x20~0x23(4칸), 모두 11칸을 쓴다.

| opcode | 명령 | 기준값 | 형식 | 동작 | flag | 클록(예상) |
|---|---|---|---|---|---|---|
| 0E | PUSH Rs | `3800` | r = Rs, operand = 0 | SP ← SP − 1, M[SP] ← Rs | - | 1 + 대기 |
| 0F | POP Rd | `3C00` | r = Rd, operand = 0 | Rd ← M[SP], SP ← SP + 1 | - | 1 + 대기 |
| 10 | RET | `4000` | 없음 | PC ← LR | - | 2 |
| 11 | LSPL imm8 | `4400` | imm8 | SP[7:0] ← imm8 | - | 1 |
| 12 | LSPH imm8 | `4800` | imm8 | SP[15:8] ← imm8 | - | 1 |
| 13 | PUSH LRL / PUSH LRH | `4C00` / `4D00` | r = 0(LR 낮은 바이트)·1(높은 바이트), operand = 0 | SP ← SP − 1, M[SP] ← LR의 그 바이트 | - | 1 + 대기 |
| 16 | POP LRL / POP LRH | `5800` / `5900` | r = 0·1, operand = 0 | LR의 그 바이트 ← M[SP], SP ← SP + 1 | - | 1 + 대기 |
| 20~23 | CALL a12 | `8000` | opcode[1:0]·r·operand = 12bit 절대 word 주소 | LR ← PC + 1, PC ← a12 | - | 2 |

- **LR(링크 레지스터)**: 16bit. CALL이 돌아올 주소(CALL 다음 명령의 word 주소)를 넣고 RET가 그 주소로 간다. CALL·RET는 메모리를 쓰지 않는다.
- 다른 루틴을 부르지 않는 루틴은 RET만 쓴다. 다른 루틴을 부르는 루틴은 들어올 때 LR을 스택에 저장하고 나갈 때 꺼낸다. 이것은 ARM Cortex-M의 `PUSH {LR}` … `POP {PC}`에 해당한다.

  ```
  routine: PUSH LRH      ; 돌아올 주소 저장(높은 바이트 먼저 — 8085와 같은 순서)
           PUSH LRL
           CALL inner    ; LR이 inner의 돌아올 주소로 바뀜
           POP  LRL
           POP  LRH      ; 원래 돌아올 주소 복원
           RET
  ```

- CALL은 opcode 4칸(0x20~0x23)을 써서 목표 주소 12bit(0~4095 word = ROM 4K word 전체)를 담는다. 기계어 = `8000` + 목표 word 주소. 예: `CALL 0x123` = `8123`.
- SP·LR은 16bit이고 **레지스터 묶음마다 따로 있다**(기본값). X·FLAGS가 묶음마다 따로 있는 지금 구조와 같다. 처리 루틴(묶음 1)은 들어올 때마다 LSPL·LSPH로 자기 SP를 정하고, 본 프로그램의 LR을 덮지 않는다.
- reset 뒤 SP = 0, LR = 0. SP를 정하지 않고 PUSH를 쓰면 `0xFFFF`(UART 영역 밖 APB 주소)에 쓰게 되어 데이터 접근 오류(fault 3)로 멈춘다. 초기화를 빠뜨리면 바로 드러나게 한 것이다.
- 예약 bit(PUSH·POP의 operand ≠ 0, PUSH LRx·POP LRx의 r = 2·3 또는 operand ≠ 0, RET의 하위 10bit ≠ 0, LSPL·LSPH의 r ≠ 0)는 지금처럼 불법 명령(fault 1)이다.
- 0x24~0x27은 긴 JMP(12bit 절대 주소)용으로 남겨 둔다. 1단계에는 넣지 않고 2단계에 넣는다(7절).
- SAP-3 방식을 쓰지 않은 이유: SAP-3의 CALL·RET는 돌아올 주소 2바이트를 메모리에 쓰고 읽어서, "명령 하나는 메모리 접근 1번"이라는 이 CPU의 원칙이 깨진다. 그러면 한 명령을 두 번 나눠 발행하는 회로, MEM/WB에서 인출 위치를 바꾸는 새 경로, 그 사이 인터럽트를 막는 회로가 필요하다. RISC 방식은 이 원칙을 지키고 CALL·RET가 2클록이다. 스택(SP·PUSH·POP)은 책 12-10절의 개념을 그대로 쓴다.

## 3. 파이프라인에 넣는 방법

### 쉬운 설명

CPU는 3칸 작업대(① 가져오기 → ② 해석·계산 → ③ 메모리 읽기/쓰기·결과 저장)로 일한다. 지금 규칙은 두 가지다. 명령 하나는 메모리를 1바이트만 읽거나 쓴다. 다음에 어디로 갈지(JMP·JZ)는 ②에서 정한다.

- PUSH·POP(LR 저장·복원 포함)은 1바이트라 지금 LD·ST와 같다. 주소만 X 대신 SP다.
- CALL은 지금 JMP와 거의 같다. 점프하면서 돌아올 주소를 CPU 안의 LR 레지스터에 넣을 뿐 메모리를 쓰지 않는다. 예: `0x0144`의 CALL이 `0x0200`을 부르면 LR = `0x0145`, 다음 명령은 `0x0200`에서 가져온다.
- RET도 JMP와 같다. 점프할 곳을 LR에서 가져온다.
- 루틴 안에서 또 다른 루틴을 부를 때만 LR을 스택에 1바이트씩 저장·복원한다(2절 예). 각각 1바이트라 규칙이 그대로 지켜진다.
- 그래서 ③에서 다음 위치를 정하는 새 길이 필요 없고, 인터럽트 규칙도 지금 그대로다.

```
0x8000 ┌──────────────────┐
       │ 계산기 변수 (0x8000~0x8018) │
       │        ...       │
       │ 처리 루틴 스택 ↓ (0x86FF부터) │
0x8700 ├──────────────────┤
       │ 본 프로그램 스택 ↓ (0x87FF부터) │
0x87FF └──────────────────┘
```

### 자세한 규칙

지금 데이터 포트는 명령 하나에 1바이트 전송 1번(ID/EX에서 주소 단계, MEM/WB에서 데이터 단계)이다. 주소는 X에서 나온다.

| 명령 | 메모리 전송 | 넣는 방법 |
|---|---|---|
| PUSH·POP·PUSH LRx·POP LRx | 1번 | LD·ST와 같다. 주소만 X 대신 SP − 1(PUSH)·SP(POP). SP와 POP LRx의 LR 바이트는 MEM/WB 완료 때 바뀐다(X와 같은 방식) |
| CALL | 없음 | ID에서 분기처럼 인출을 a12로 돌린다(지금 JMP와 같은 경로). LR ← PC + 1은 MEM/WB 완료 때 쓴다(X와 같은 방식) |
| RET | 없음 | ID에서 LR 값으로 인출을 돌린다(JMP와 같은 2클록). 목표만 명령 bit 대신 LR에서 온다 |

- 의존: SP를 바꾸는 명령 바로 뒤에서 SP를 읽는 명령(PUSH·POP·PUSH LRx·POP LRx·LSPL·LSPH)은 지금의 X 규칙처럼 1클록 기다린다. LR을 바꾸는 명령(CALL·POP LRx) 바로 뒤에서 LR을 읽는 명령(RET·PUSH LRx)도 1클록 기다린다. 예: `POP LRH` 바로 뒤의 RET는 1클록 기다린다. 루틴 첫 명령 `PUSH LRH`는 CALL 바로 뒤지만, CALL이 인출을 돌리는 동안 CALL이 끝나 두 명령이 파이프라인에서 겹치지 않으므로 메모리 대기가 없으면 기다리지 않는다(실측은 `isa_table.md` "클록" 절, 2026-11-24 정정). POP 바로 뒤에서 그 레지스터를 쓰면 지금 LD 규칙처럼 1클록 기다린다.
- 인터럽트: 새 명령은 모두 한 번에 발행되므로 지금 규칙 그대로다(ID/EX의 명령을 버리고 RETI 뒤 다시 실행). 처리 루틴은 묶음 1의 SP·LR을 쓰므로 본 프로그램의 LR을 덮지 않는다.
- 오류: PUSH·POP의 데이터 접근 오류는 지금처럼 fault 3으로 멈추고, 그 명령의 SP·레지스터·LR 변경은 반영하지 않는다.
- 스택 위치(펌웨어 기본값): RAM `0x8000~0x87FF`의 맨 위. 묶음 0은 SP = `0x8800`(첫 PUSH가 `0x87FF`), 묶음 1(계산기 처리 루틴)은 `0x8700`. 변수는 지금처럼 `0x8000~0x8018`. 스택은 캐시를 거치므로 hit이면 대기 0, miss면 약 94~207클록이다.
- 바뀌는 RTL: `cpu8_isa.vh`(opcode), `cpu8_decoder.v`(새 명령·예약 bit·읽기/쓰기 대상 SP·LR), `cpu8_top.v`(SP·LR 묶음, 데이터 주소 X/SP 선택, CALL·RET 인출 재지정, SP·LR 의존 검사). ALU·레지스터 파일은 그대로다. 두 번 나눠 발행하는 회로, MEM/WB 인출 재지정 경로, 인터럽트 막기는 필요 없다.

## 4. 새 연산 (계산기 규약 변경안)

### 쉬운 설명

쓰는 방법은 지금과 같다(숫자 줄 `A,B` 뒤에 연산 이름).

| 입력 | 응답 | 이유 |
|---|---|---|
| `2,10` → POW | `POW:1024` | 2를 10번 곱함 |
| `-2,15` → POW | `POW:-32768` | 16bit에 딱 들어감 |
| `2,15` → POW | `ERR OVER` | 32768은 16bit 최대 32767을 넘음("너무 크다"는 새 오류) |
| `2,-1` → POW | `ERR RANGE` | 2의 −1제곱은 0.5라 정수가 아님 |
| `0,0` → POW | `POW:1` | 정해지지 않은 값이라 1로 정함 |
| `12,18` → GCD | `GCD:6` | 12와 18을 모두 나누는 가장 큰 수. 18,12 → 12,6 → 6,0 → 6 |
| `-12,18` → GCD | `GCD:6` | 부호는 무시 |
| `0,0` → GCD | `GCD:0` | 정해지지 않은 값이라 0으로 정함 |
| `50,0` → SQR | `SQR:7` | 1·3·5·7·9·11·13을 빼면 1이 남음 → 7번(7×7 = 49 ≤ 50 < 64) |
| `-1,0` → SQR | `ERR RANGE` | 음수의 제곱근은 없음. B는 쓰지 않음 |

### 자세한 규칙

입력은 지금처럼 −128~127, 결과는 부호 있는 16bit(−32768~32767), 한 줄 최대 15자다. 연산 이름은 지금처럼 3글자이고 대소문자를 구분하지 않는다.

| 연산 | 응답 | 예 | 규칙(기본값 포함) |
|---|---|---|---|
| POW | `POW:<A의 B제곱>` | `2,10` → `POW:1024`, `-2,15` → `POW:-32768` | B < 0 → `ERR RANGE`. 결과가 −32768~32767 밖 → **`ERR OVER`(새 오류)**. 0의 0제곱 = 1 |
| GCD | `GCD:<최대공약수>` | `12,18` → `GCD:6`, `-128,0` → `GCD:128` | 부호를 떼고 계산. GCD(0,0) = 0 |
| SQR | `SQR:<A의 정수 제곱근>` | `50,0` → `SQR:7`, `127,9` → `SQR:11` | B는 쓰지 않는다(숫자 줄은 지금처럼 A,B 둘 다 필요). A < 0 → `ERR RANGE` |

- `ERR OVER`는 POW에만 생긴다. 다른 오류(`ERR SYNTAX`·`ERR NOARG`·`ERR DIV0`·`ERR RANGE`)의 뜻은 그대로다.
- 펌웨어 구성(기본값): 루틴 `MUL16`(16bit × 8bit, 넘침 검사), `DIVMOD`(나눗셈·나머지), `PRINT`(숫자 출력), `TXWAIT`(송신 대기)를 CALL로 부른다. POW는 `MUL16`을 B번(넘치면 바로 멈춤), GCD는 유클리드 호제법으로 `DIVMOD`의 나머지를 반복, SQR은 1·3·5…를 빼 가며 센다(곱셈 없이 최대 12번).
- 지금 연산(ADD·SUB·MUL·DIV)의 응답은 바뀌지 않는다. 기존 시험 사례는 그대로 통과해야 한다.
- MSPM0 S2 순서: ADD → SUB → MUL → DIV → POW → GCD → SQR → ADD.

## 6. 시험 계획

1. CPU 단위
   - 명령별 사례: PUSH·POP 순서, CALL·RET, LR 저장·복원으로 중첩(깊이 8), 스택에 저장한 LR의 바이트 순서, SP 순환, SP 미설정 fault 3, 예약 bit fault 1, SP·LR 의존 기다림(CALL 직후 `PUSH LRH`, `POP LRH` 직후 RET).
   - 메모리 대기(지연 모드 전부)에서 PUSH·POP·LR 저장, 대기 중 reset.
   - 인터럽트: 처리 루틴 안의 CALL·RET(묶음 1 SP·LR)가 본 프로그램의 SP·LR을 바꾸지 않음, CALL·RET 직전·직후의 인터럽트 진입.
   - 기준 모델 대조: 무작위 프로그램에 새 명령을 섞어 명령마다 PC·레지스터·X·SP·LR·FLAGS·메모리 접근 비교.
   - 기존 88개 회귀 프로그램은 완료 명령 수·클록·stall이 바뀌지 않아야 한다.
2. 클록 측정: `measure_cpu8_cycles.py`에 push·pop·call_ret 사례를 더해 `isa_table.md`의 클록 열을 실측값으로 채운다.
3. 계산기: 통합 TB `calc`에 새 연산 경계값(`-2,15` POW·`2,15` OVER·`0,0` POW·`-128,0` GCD·`0,0` GCD·`127,0` SQR·`-1,0` SQR 등)과 무작위 줄, 보드 TB, 보드 실물(PC 화면·MSPM0).
4. 전후 수치 표: 펌웨어 크기(word), `V_PHASE`·복사된 송신 대기 루프 수, 연산별 최악 클록.
5. Codex 검증: CPU 모듈 요청서(VR-0xx_cpu8_v2) → 통합 요청서(VR-0xx_soc_v2) → 각각 PASS 뒤 사용자 승인으로 main 병합(병합 규칙은 [verification/README.md](../verification/README.md) 4절).

## 7. 2단계 — 숫자 16bit와 시프트·회전·ALU·분기 명령 (1단계 뒤)

- 결정(사용자, 2026-11-18 "A안으로 가자"): 2단계에 숫자 16bit 확장과 CPU 시프트·회전 명령을 함께 넣는다(A안). 비교한 B안(16bit 숫자만, CPU 그대로)은 쓰지 않는다. 세부 설계는 1단계를 마친 뒤 이 절을 넓혀 정한다. 아래 "기본값"은 Claude가 정한 것이며 바꿀 수 있다.
- 결정(사용자, 2026-11-20 "2단계에 넣어"): 책을 바탕으로 한 개선안 중 아직 계획에 없던 ALU·분기 명령(논리 OR·XOR·NOT, 즉시값 연산, 반대 조건·부호 분기)도 2단계에 함께 넣는다. 시프트·회전과 같은 종류(1클록 ALU·분기 명령, 새 레지스터 없음)라서 같은 단계에서 설계·검증한다. 이어서(사용자 "둘다 추가하고 커밋 푸쉬해") 처음 기본값에서 뺐던 ADCI·SBCI와 긴 JMP도 넣는다. ADCI·SBCI는 레지스터가 R0~R3 4개뿐이라 16bit 숫자 둘을 올리면 상수를 담을 빈 레지스터가 없는 문제를 덜고, 긴 JMP는 1단계 CALL의 12bit 절대 주소 경로를 LR 저장 없이 쓰는 것이라 비용이 작다.
- 숫자: 입력은 −32768~32767, 결과는 부호 있는 32bit다. CPU는 8bit 그대로 두고 펌웨어가 여러 바이트로 계산한다(ADD·ADC 연결). 가장 긴 숫자 줄은 `-32768,-32768`(13자), 가장 긴 MUL 응답은 `MUL:-1073709056`(15자)이다.
- 새 명령(기본값) 18개. 기존 명령과 1단계 명령의 opcode는 바꾸지 않는다. 긴 JMP는 비워 둔 0x24~0x27(4칸)을 쓰고, 나머지 17개는 1단계 뒤 남는 빈 opcode 0x1C~0x1F·0x28~0x3F(28칸) 중에서 2단계 설계 때 배정한다. 형식·flag·클록 규칙은 같은 종류의 기존 명령([isa_table.md](isa_table.md))을 따른다.

  | 묶음 | 명령 | 형식 | 동작 | flag | 책 근거 |
  |---|---|---|---|---|---|
  | 시프트·회전 | SHL Rd, SHR Rd | r = Rd | 한 bit 밀기, 밖으로 나간 bit → C | Z·N, C = 나간 bit, V = 0 | 20장 |
  | | ROL Rd, ROR Rd | r = Rd | C를 거쳐 한 bit 회전(8085 RAL·RAR 방식) | Z·N, C = 나간 bit, V = 0 | 20장 |
  | 논리 | OR Rd,Rs, XOR Rd,Rs | RR | Rd ← Rd \| Rs, Rd ← Rd ^ Rs | AND와 같음(Z·N, C = 0, V = 0) | SAP-2·3 ORA·XRA |
  | | NOT Rd | r = Rd | Rd ← ~Rd | AND와 같음 | SAP-2·3 CMA(8085 CMA는 flag를 바꾸지 않으나 이 CPU의 논리 명령 규칙을 따름) |
  | 즉시값 | ADDI·ADCI·SUBI·SBCI·CMPI·ANDI Rd,imm8 | R + imm8(LDI와 같음) | ADD·ADC·SUB·SBC·CMP·AND의 Rs 자리에 imm8 | 대응 명령과 같음 | 12-6절 ADI·ACI·SUI·SBI·CPI·ANI |
  | 분기 | JNZ·JNC·JN·JV rel8 | rel8 | Z = 0·C = 0·N = 1·V = 1이면 분기 | - | SAP-3 JNZ·JNC·JM(N = 1). JV는 책 밖(8085에는 V flag가 없음, 이 CPU에는 V가 있음) |
  | | JMP a12(긴 JMP) | opcode[1:0]·r·operand = 12bit 절대 word 주소(CALL과 같음), 0x24~0x27 | PC ← a12(LR은 바꾸지 않음) | - | 8085 JMP(16bit 절대 주소). 분기 ±128칸을 넘는 점프용 |

- 클록(예상): 모두 기존 규칙과 같다. ALU 명령은 1클록이고 바로 앞 명령이 쓴 레지스터·flag를 읽으면 +1, 분기는 분기함 2클록·통과 1클록이다. 구현 뒤 `measure_cpu8_cycles.py`에 사례를 더해 실측한다.
- 클록(긴 JMP): JMP rel8과 같이 2클록(분기, 이미 인출한 다음 명령을 버림)으로 예상한다.
- 효과(지금 펌웨어 `calc.asm` 853명령을 스크립트로 센 값, 2026-11-11): 상수 LDI 직후 그 레지스터로 연산하는 곳 84곳(CMP 43, ADD 11, SUB 10, AND 8, SBC 8, ADC 4)이 모두 즉시값 명령 하나로 준다. JZ·JC 바로 뒤 JMP 27곳이 반대 조건 분기 하나로 준다. 분기 거리를 잇는 점프 한 줄짜리 징검다리 25곳이 긴 JMP로 없어진다. 부호(sA xor sB)를 ADD+AND로 만드는 곳이 XOR 하나로 준다. 2단계 펌웨어는 16bit로 다시 쓰므로 실제 수치는 그때 다시 센다.
- 넣지 않는 것(기본값)
  - INC·DEC: ADDI ±1로 대신한다. 8085 INR·DCR처럼 C를 바꾸지 않는 이점은 명령 순서(자리올림을 쓴 뒤 횟수를 셈)로 대신한다.
  - ORI·XORI: 지금 펌웨어에 쓰는 곳이 없고, 마스크는 ANDI·NOT으로 만든다.
  - X 포인터 명령(책 12-8·12-9의 HL 방식, X ↔ 레지스터 이동 등): 지금 계산기에는 없어도 동작한다(응답 글자는 LDI+ST로 쓴다). 레지스터와 주소 사이에 새 경로가 생기는 변경이라, 배열·버퍼를 다루는 기능을 넣을 때 다시 검토한다.
- 곱셈·나눗셈(기본값): MUL은 시프트-덧셈, DIV는 시프트-뺄셈(복원 나눗셈)으로 16번 반복한다. 지금 방식(반복 덧셈·뺄셈)을 16bit에 그대로 쓰면 최악 약 43만 클록(약 4 ms)이고, 시프트 방식은 수백 클록(약 4 µs)이다(둘 다 추정: 반복 1회 약 13클록 × 32,768번, 100 MHz 기준). 두 방식의 실측값을 전후 수치 표로 남긴다.
- POW(기본값): 결과가 32bit 범위 밖이면 `ERR OVER`.
- DIV 응답 길이(기본값): 16bit에서는 `DIV Q:-10922 R:-1`처럼 최대 17자가 되어 지금 규약(15자)과 LCD 한 줄(16칸)을 넘는다. DIV 형식은 그대로 두고 응답 최대 길이를 17자로 늘린다. STM32는 16칸을 넘는 글자를 LCD 2행에 이어 표시한다(줄 내용을 해석하지 않는 방식은 유지). 따라서 1단계와 달리 2단계에서는 STM32·PC 도구·MSPM0의 길이 검사가 바뀐다.
- 검증: 1단계처럼 CPU 모듈 요청서와 통합 요청서를 따로 낸다(각각 Codex PASS 뒤 사용자 승인으로 main 병합).
